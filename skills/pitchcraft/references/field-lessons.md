# Field Lessons from Prior Roadshows

## Speed is a workflow design problem

Requests for speed favor reuse and shorter working batches. Explicit requests for uninterrupted completion allow Emergency mode within authorized scope; `继续` alone does not cancel a pending sample gate. State necessary assumptions once and keep local revision capability.

Do not remove all control. Keep internal gates for source truth, slide readability, text accuracy, and packaging integrity.

## Product style must be discovered before generation

One prior roadshow succeeded when it first read the local product's design language and then reused product UI and visual elements in a restrained light deck. The lesson is not `use a light background`; it is `derive the presentation system from the product before prompting slides`.

## GitHub workflow can be the strongest proof object

Another roadshow began from a specific GitHub PR describing the real workflow. Repository history, PRs, issues, and working product flow can be stronger evidence than generic marketing copy. Treat them as proof sources, then translate the workflow into one continuous visual path.

## Demo repositories may not be product truth

A temporary livedemo may be optimized for presentation and later discarded. Resolve the durable repository, current worktree, and maintained product surface before extracting claims or visual style.

## Image text needs its own QA loop

Full-slide generation can produce attractive pages with incorrect Chinese. Compare required words and numbers page by page. When a risky term repeatedly fails, reduce on-slide text or move explanation into speaker notes; do not accept incorrect text for speed.

## Revision must stay local

Roadshow decks change after first delivery: page insertion, slogan changes, roadmap edits, and business-path additions are normal. Stable filenames, a Deck System Contract, and image-only page replacement let the system update one page without disturbing the rest.

## Image generation is not integrated progress

Count completed, assembled and checked pages separately from generated assets. Reuse usable cleaned assets immediately. Full-page review does not mean merging existing picture objects, and individual processing does not mean exposing tiny intermediate strips. Preserve approved pages; stop when the requested checks pass. See [editable-handoff.md](editable-handoff.md) for the image-to-editable boundary and resume rules.
