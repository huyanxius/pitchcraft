# 使用指南

## 先选终点

想快速得到可演示的精致页面，选择图片版：每页是一张完整图片，PPT 可以打开、放映和调整页序，但不能直接修改图片内部文字。

需要后续改文案或移动素材，再选择可编辑版。它沿用认可页面的构图，清掉素材中的目标文字，并恢复对应的原生对象。复杂插图仍可能是独立位图；不能保证每个像素都变成矢量。

两个阶段可以分开使用。提供认可 PNG 或图片 PPT 时直接转换；提供已经拆好的 PPT 时直接修复，不从生成初稿开始。

## 输入什么

- 仓库路径或 GitHub 仓库/PR URL：提取产品事实、品牌资产和视觉线索。
- 正文、讲稿、比赛要求：确定内容、受众、时长和必须出现的事实。
- 认可的样页：作为版式、字体气质、密度和材质参考。
- 图片 PPT、PDF、PNG 或部分可编辑的 PPTX：从现有成果继续。

仓库不是必填项。资料足够时可以直接制作。没有来源的指标、人物、成效与获奖事实不会补造。

## 三个技能如何配合

`pitchcraft` 负责产品判断、故事线、速度与交付范围；`rw-consulting-ppt` 负责整页图像生成及视觉治理；`image-ppt-to-editable` 负责文字恢复、底图清理、素材与透明度检查。

RW 的“每页一张图、零可编辑文本”只约束图片阶段。转换后不再套用这项检查；图片版和编辑版另存，名称明确。宿主需要加载当前可用的图像生成与 Presentations 工具，这些工具不随本仓库安装。

## 复用与修改

样页认可后锁定整套风格；完整两阶段已经授权时，转换不再重复询问一遍。默认会先完成一张转换页来检查工具、字体和回装效果，再按页或短批次继续。

底图必须真正清字，不能用色块或新文字盖住脏图。已拆好的图片数量、位置、尺寸、裁切、旋转与组织保持不变。生成器给长条图增加外部留白时，核对真实内容边界再还原尺寸，不直接拉伸。

文字修改优先改原生文本。若要图片版也同步，请明确说明；否则它保留为之前的图片基准，避免每改一句话都重新生成整页。

## 辅助脚本

脚本路径相对仓库根目录。先用 `--help` 查看参数：

```bash
python3 skills/pitchcraft/scripts/scan_product_repo.py --help
python3 skills/pitchcraft/scripts/package_image_deck.py --help
python3 skills/image-ppt-to-editable/scripts/remove_chroma_key.py --help
```

扫描器只读提取候选资料，不能替代事实判断。打包器要求 `slide_*.png`，仅创建图片版 PPTX，不负责生成图片或转换编辑对象。抠图工具只适用于合适的纯色底，需要 Pillow，不是通用复杂照片去背景服务。

## 常见问题

**只有一个技能入口，为什么安装三个目录？** 入口负责流程，两个配套技能承担不同制作阶段。一起安装即可，不必用户手动切换工作流。

**没有图像生成工具怎么办？** 可以整理证据、正文与提示词，但无法完成图片生产；不会自动改走代码绘制页面。

**没有 PPTX 转换运行时怎么办？** 图片版仍可交付。需要编辑版时必须补齐宿主转换能力，不能把图片版说成可编辑成品。

**中文变成方框怎么办？** 先比较源页和输出页在同一个渲染器中的表现。如果两者都出问题，先查字体与 fontconfig，别直接改掉原文或判定 PPT 损坏。

**“商业级”是不是保证？** 它是目标质量标准：证据、层级、准确文字、整套风格与可维护对象。模型输出受素材和工具影响，必须检查，没有认证或固定耗时保证。

**能用示例里的图片和品牌吗？** 示例用于展示工作流目标，不是可自由复用的素材库。使用你自己的素材和品牌。
